# اتصال یک‌کلیکی گوگل

## این چیست؟
زول با یک دکمه به حساب گوگل وصل می‌شود، مثل Claude. بعد از آن به **جیمیل، درایو، شیت، داکس، تقویم، مخاطبین و تسک‌ها** دسترسی دارد. خواندن آزاد است. ارسال ایمیل و هر ساختن یا تغییری **همیشه اول از تو تأیید می‌گیرد**.

## چه کار می‌کند؟
1. در اپ زول: **منو ← اتصال‌ها ← گوگل ← «اتصال به گوگل»**.
2. صفحهٔ اجازهٔ گوگل باز می‌شود. حساب را انتخاب کن و Allow را بزن. اپ هنوز در حالت Testing است، پس پیام «Google hasn't verified this app» می‌آید و باید **Advanced ← Go to Zoul** را بزنی.
3. صفحهٔ «گوگل وصل شد» نشان داده می‌شود. «برگشت به زول» را بزن.
4. حالا به ایجنت بگو، مثلاً «ایمیل‌های نخوانده‌ام را خلاصه کن» یا «این‌ها را به شیت هزینه‌ها اضافه کن».

**ابزارهای ایجنت** (دو سرور MCP):

| سرور | ابزارها | سیاست |
|---|---|---|
| `google` (خواندن) | `gmail_search`، `gmail_read`، `drive_search`، `drive_read` (Docs/Slides به متن، Sheets به CSV، PDF و متن)، `sheets_info`، `sheets_read`، `docs_read`، `calendar_events`، `contacts_search`، `tasks_list` | آزاد، ولی «دادهٔ خصوصی» حساب می‌شود. بعد از آن، فرستادن داده به مقصد ناآشنا تأیید می‌خواهد |
| `google_write` (نوشتن) | `gmail_send`، `gmail_create_draft`، `drive_create_file`، `sheets_create`، `sheets_append`، `sheets_update`، `docs_create`، `docs_append`، `calendar_create_event`، `tasks_add` | **همیشه تأیید** (`google_write__*` در `always_ask_tools`، با ریسک `sensitive`) |

- **قطع اتصال** از همان کارت انجام می‌شود: توکن در گوگل باطل و از دیتابیس پاک می‌شود. **اتصال دوباره** هم جای حساب قبلی را می‌گیرد.
- اگر گوگل اتصال را رد کند (دسترسی پس گرفته شده یا توکن منقضی شده)، ابزارها پیام «دوباره اتصال بزن» برمی‌گردانند.

## امنیت
- refresh token با **Fernet** رمزنگاری و در دیتابیس ذخیره می‌شود. کلیدش از `SECRET_KEY` مشتق می‌شود. مدل، UI و پنل ادمین هیچ‌وقت توکن را نمی‌بینند.
- شروع اتصال، وضعیت و قطع اتصال فقط با **توکن زول** (`OPENMUSE_SERVER_TOKEN`) کار می‌کنند. `state` امضاشده است و ده دقیقه اعتبار دارد. پس کسی بیرون از زول نمی‌تواند حساب گوگل خودش را به ایجنت تو وصل کند.
- هر چیزی که از ایمیل یا فایل خوانده می‌شود **داده است، نه دستور** (برای جلوگیری از prompt injection). این در دستور سرور MCP هم آمده است.
- ⚠️ اگر `SECRET_KEY` عوض شود، توکن ذخیره‌شده دیگر باز نمی‌شود و فقط باید دوباره «اتصال» زد.

## تنظیمات
| متغیر | توضیح |
|---|---|
| `GOOGLE_OAUTH_CLIENT_ID` | از Google Cloud ← Clients (Web application) |
| `GOOGLE_OAUTH_CLIENT_SECRET` | همان‌جا. در همروش «متغیر امن» |
| `ZOUL_PUBLIC_URL` | پیش‌فرض `https://zoul.darkube.ir`. آدرس برگشت از روی آن ساخته می‌شود |

**Google Cloud** (پروژهٔ `zoul-515815`):
- APIهای Gmail، Drive، Sheets، Docs، Calendar، People و Tasks فعال‌اند.
- صفحهٔ اجازه External است و ۱۰ مجوز دارد.
- آدرس برگشت: `https://zoul.darkube.ir/connectors/google/callback`
- ایمیل کاربر باید در **Audience ← Test users** باشد.

## تست
- `connectors/tests.py` (۲۵ تست، همه با گوگل ساختگی):
  - رمزنگاری.
  - قفل بودن APIها بدون توکن.
  - لینک اجازه با همهٔ مجوزها.
  - رد شدن state جعلی یا قدیمی.
  - ذخیرهٔ رمزنگاری‌شده و جایگزینی حساب.
  - قطع اتصال با revoke.
  - تازه کردن توکن منقضی.
  - ابزارهای جیمیل، درایو و شیت.
  - خطای «وصل نیست».
- دستی: سرورهای MCP با کلاینت MCP خود OpenMuse بالا آمدند و ۲۰ ابزار را نشان دادند.

## نکته‌ها و محدودیت‌ها
- **حالت Testing:** گوگل در این حالت توکن‌ها را بعد از حدود **۷ روز** منقضی می‌کند. وقتی زول گفت «دوباره اتصال بزن»، از کارت گوگل «اتصال دوباره» را بزن. برای رفع این محدودیت باید اپ را Publish کرد، که صفحهٔ خانه و سیاست حریم خصوصی روی یک دامنهٔ تأییدشده می‌خواهد. یعنی بعد از اینکه دامنهٔ خود زول را داشتیم.
- **تک‌کاربره:** فعلاً یک حساب گوگل. با آمدن ورود OTP، برای هر کاربر جدا می‌شود.
- **پیوست‌ها:** پیوست ایمیل فقط اسمش خوانده می‌شود و دانلود نمی‌شود.
- **کانکتور ایمیل IMAP خود OpenMuse** هنوز هست و مستقل از این کار می‌کند. برای جیمیل همین اتصال گوگل ساده‌تر است.
