# پروژهٔ زول: هدف، معماری، تصمیم‌ها

## هدف
یک ایجنت شخصی شبیه **Muse متا** (نه Manus):
- با کامپیوتر یا sandbox خودش کار می‌کند و بعد از بستن اپ هم ادامه می‌دهد.
- قبل از هر کار برگشت‌ناپذیر (ارسال ایمیل و پیام، خرید) از کاربر تأیید می‌گیرد.
- کاربر مدل را انتخاب می‌کند (Claude، Gemini، ChatGPT، DeepSeek) و کلید API خودش را می‌دهد (BYOK).
- کانکتورها: جیمیل، تقویم، تلگرام، واتساپ، اینستاگرام.
- **فعلاً تک‌کاربره و بدون ورود.** بعداً ورود با OTP صبانوین و مدل User مثل «خانواده من»، و نمونهٔ جدا برای هر کاربر.

## معماری

```
                    ┌──────────────── کانتینر زول (همروش) ─────────────────┐
مرورگر / گوشی ───►  │  nginx (:8000)                                        │
                    │   ├─ / ، /api ، /ws ──────────► OpenMuse (:8787)      │
                    │   │                              UI، Sentinel، Vault، │
                    │   │                              حافظه، ابزارها        │
                    │   └─ /admin ، /zoul ، /health ، /engine ، /static      │
                    │        └────────► gunicorn + جنگو (:8001)             │
                    │                    engine/openmuse_client ──► :8787   │
                    └───────────────────── /data (دیسک دائمی) ──────────────┘
                                                      │
                                                      ▼
                                          DeepSeek API (و بعداً LiteLLM)
```

- **جنگو** پنل و لایهٔ مالکیت زول است: کاربرها و تنظیمات (بعداً)، و هر رابطی که خودمان می‌سازیم.
- **OpenMuse** موتور است: حلقهٔ ایجنت، ابزارها، Sentinel (تأییدها)، Vault، حافظه، هدف‌ها و تریگرها.
- این دو فقط از راه API موتور با هم حرف می‌زنند و فقط از یک فایل (`engine/services/openmuse_client.py`). عوض کردن موتور یعنی عوض کردن همین فایل.
- **nginx** تنها پورت بیرونی (`8000`) را بین این دو تقسیم می‌کند ([gateway.md](features/gateway.md)).
- هر سه پروسه در یک کانتینر اجرا می‌شوند، هم روی همروش و هم لوکال با docker-compose.

## مراحل (هر مرحله با تأیید حسین)
1. ✅ **ریپو و اسکلت:** جنگو (`home`، `engine`)، Docker، تنظیمات OpenMuse و مستندات.
2. ✅ **سرویس همروش:** `zoul.darkube.ir`، پلن ۲ گیگ و ۱ هسته، دیسک ۱ گیگ روی `/data`، یک replica. bubblewrap کار نمی‌کند (shell بدون جعبه، با تأیید). nginx برای UI موتور.
3. **جیمیل و تقویم** با اکانت تست؛ خواندن آزاد، ارسال با تأیید.
4. **LiteLLM** روی سرور بیرون ایران برای انتخاب بین Claude، Gemini، GPT و DeepSeek.
5. **سرور MCP تلگرام** (فقط‌خواندنی)، بعد واتساپ و اینستاگرام.
6. **ورود با OTP** و مدل User مثل «خانواده من»، و نمونهٔ جدا برای هر کاربر.

## ریسک‌ها
- **رم ۲ گیگ:** بدون مرورگر احتمالاً کافی است. با Chromium ریسک دارد و ۴ گیگ بهتر است.
- **اینترنت ایران:** سرور داخل ایران معمولاً به OpenAI، Claude، Gemini و تلگرام دسترسی ندارد. برای این‌ها رله یا سرور بیرون لازم است.
- **bubblewrap روی همروش کار نمی‌کند:** shell و Python بدون جعبه اجرا می‌شوند، ولی همیشه پشت تأییدند. اگر لازم شد، اجرای shell را به یک sandbox جدا ببریم.
- **prompt injection:** پیام و ایمیل دریافتی می‌تواند به ایجنت دستور بدهد. ارسال و حذف همیشه با تأیید است.
